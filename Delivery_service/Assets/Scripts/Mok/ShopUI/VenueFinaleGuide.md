# 마지막 배달 코드 안내

## 수정할 파일 찾기

| 변경할 내용 | 담당 파일 |
|---|---|
| 미션 시작 조건, 단계 전환, 상호작용, 완료·실패·재시도 | `VenueFinale.cs` |
| 조직원 생성, 화면 밖 생성 위치 확인, 생성 대기, 적 정리 | `VenueFinaleEnemies.cs` |
| 카메라, 조작 잠금·복원, 승하차, 퇴장 연출, 귀가 후 민기 배치 | `VenueFinaleCinematics.cs` |
| 목표 문구, 자막 표시 시간, 목적지 마커, 탈출 경로 표시 | `VenueFinalePresentation.cs` |

`VenueFinale`가 미션 진행을 결정하고 나머지 세 클래스에 처리를 맡긴다. 보조 클래스는 일반 C# 클래스이므로 씬에 컴포넌트를 새로 붙일 필요가 없다. 기존 씬의 `VenueFinale` 필드와 다른 스크립트에서 호출하는 함수는 유지했다.

## 진행 흐름

준비 완료 → 오프닝 → 납품 출입구 → 피자 내려놓기 → 관찰·대화 → 발각 → 내부 탈출 → 외부 탈출 → 차량 탑승 → 직접 운전 → 차량 버리기 → 귀가·민기 대화 → 매장 습격 챕터

잠입 중 쫓겨나면 출입구로 돌아가 다시 입장한다. 실패·취소 시에는 카메라와 조작 상태, 적, 교통 상태를 정리하며 준비 미션 성과는 유지한다.

## 함께 쓰는 기존 기능

- 경비 시야와 의심 판정: `VenueStealth`
- 차량 운전: `VenueGetawayDrive`
- 외부 추격: `VenueStreetPursuit`
- 이후 매장 습격: `ShopEscapeChapter`

이 기능들을 주 미션 파일로 다시 합치지 않는다. 주 미션은 단계를 결정하고 각 기능은 자기 역할을 처리한다. 기존 대사 필드와 대사 데이터 연결도 그대로 사용한다.

## 확인 방법과 범위

`Editor/VenueFinaleRefactorCheck.cs`의 `RunBatch`는 JJinCity를 열고 Play Mode에서 단계 연결을 검사한다. 실행 전 작업을 저장하고 Game 창에 포커스를 둔다. 결과는 프로젝트의 `Logs/Venue-refactor-check.txt`에 남는다.

입장, 재입장, 관찰, 발각, 탈출, 화면 안 적 생성 거부, 승하차, 일시정지, 운전, 귀가, 취소와 재시도를 확인한다. 검사에서는 선행 미션과 일부 이동 위치·전투 조건을 준비하므로 처음부터 끝까지 직접 걷고 싸우는 플레이 테스트를 대신하지 않는다. 저장된 재료·경제 데이터는 검사 종료 후 복원한다.

씬에 저장되는 필드 이름이나 미션 단계 순서를 바꾸면 기존 씬 연결이 달라질 수 있다. 단순 가독성 정리에서는 이 부분을 유지한다.
