# 매장 습격 · 공원 전투 · 체포 코드 안내

| 수정할 내용 | 담당 파일 |
|---|---|
| 마지막 배달 이후 챕터 시작, 매장 탈출, 구치소·감옥 연결, 초기화 | `ShopEscapeChapter.cs` |
| 공원 도착, 교전·부상·경찰 출동·통화·체포 단계의 순서와 조건 | `ParkEscapeSequence.cs` |
| 민기 따라오기, 걷기·달리기, 문 통과, 부상 자세와 복원 | `ShopEscapeCompanion.cs` |
| 조직원 증원·엄폐, 민기 지원 사격, 전투 정지와 조직원 철수 | `ParkEscapeCombat.cs` |
| 카메라 방향, 경찰 통화 자세, 사이렌·경광등과 복원 | `ParkEscapeCinematics.cs` |
| 습격 중 일반 시민 숨김과 종료·초기화 시 복원 | `ParkEscapeCrowd.cs` |

두 진행 컴포넌트가 **언제 다음 단계로 넘어가는지** 결정하고, 네 보조 클래스가 **이동·전투·화면 동작**을 처리한다. `Tick`은 단계별 함수로 나눠 순서를 읽기 쉽게 했다. 보조 클래스는 일반 C# 클래스이므로 씬에 새 컴포넌트를 붙이지 않는다.

## 기존 기능과 연결

- `VenueFinale`: 마지막 배달에서 넘어오는 시작점, 플레이어 조작·적 목록 관리
- `ParkCoverActor`: 각 인물의 엄폐 동작
- `ParkPoliceArrivalBehaviour`: 경찰차 이동, 문 열기, 하차·접근·총 겨누기
- `PrisonPreviewTransition`: 구치소 이후 감옥 둘러보기 씬 전환

위 기능의 기존 연결을 유지했다. 씬에 저장된 필드 이름, 단계 순서, 외부에서 쓰는 호출 함수와 대사는 변경하지 않았다. 대사는 기존 Inspector 필드와 대사 편집 도구에서 수정한다. `ShopEscapeChapter`의 공원 시퀀스가 없는 경우 사용하는 이전 체포 분기도 남겼다.

## 진행 흐름

매장 권총 획득 → 민기와 공원으로 이동 → 위협 방향을 보는 컷씬 → 조직원들이 엄폐 위치에 도착 → 민기와 교전 → 민기 부상 → 민기 방어 → 경찰차 도착·하차 → 경찰 통화 → 조직원 철수 → 두 사람 체포 → 구치소 → 감옥 씬

재시작할 때는 `ResetChapter`에서 보조 클래스까지 정리한다. 자세를 직접 조정하는 코드는 매 프레임 기준 자세를 사용하고, 체포가 끝나면 원래 애니메이터를 복원한다.

## 확인 방법

에디터의 `Tools > Delivery Service > 검사 > 매장 습격·공원 전투·체포` 메뉴로 실제 JJinCity 씬 검사를 실행할 수 있다. 열린 씬을 먼저 저장하고 Game 창에 포커스를 둔다. 결과는 프로젝트의 `Logs/Escape-refactor-check.txt`에 남는다.

검사는 권총 획득, 초기화·재시작, 동료 이동, 공원 전투, 부상, 경찰 하차·통화·체포와 감옥 전환을 다룬다. 선행 미션과 이동 위치는 테스트에서 준비하고 일부 대기 시간을 줄인다. 전체 경로를 직접 조작하는 수동 플레이와는 구분한다. 테스트 종료 후 저장된 재료·경제 데이터를 복원한다.

확인 결과: Unity Play Mode 검사 50개 통과 (일반 시민 숨김·복원 검사 포함). 저장된 공개 필드·기본값 63개, 공개 함수 18개와 단계 순서가 변경 전과 일치한다. 감옥 씬 전환까지 확인하고 테스트가 사용한 저장 데이터를 복원했다. 이동 위치는 보행 가능한 지면을 사용하며, 선행 귀환 컷씬에서 활성화되는 민기도 검사 시작 시 활성화한다.

매장 습격 준비부터 공원 체포까지 일반 시민은 비활성화한다. 미션 중 다시 활성화된 시민도 주기적으로 숨긴다. 민기·미션 조직원·경찰은 제외하며, 종료·초기화·비활성화 시 직접 숨긴 시민만 복원한다.
